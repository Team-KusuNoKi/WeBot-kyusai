# 11月の救祭 — 謎解きチャット

現在のアプリURLは https://team-kusunoki.com/11月の救祭/app/ です。旧 `/app/` から301転送します。日本語URLとパーセントエンコード済みURLは同じページを開き、再開番号・保存データを引き続き使用できます。

スマートフォンを基準にした謎解きチャットと、入口用ウェブサイトのローカル版。N1は選択問題、N2・N3は漢字入力の問題です。N4〜N5も実装済みです。N5.5は語群から2語を選んで仮説を完成させる問題です。考察カードは仮データです。2026-10-29に公式サイトの https://team-kusunoki.com/app/ へ、ここまでのシナリオ・画面変更を公開しました。公開内容と検証結果は `VERIFICATION.md` に記録しています。2026-10-29に6桁番号によるCloudflare進行保存と、`000000`の非保存デバッグモードも本番公開しました。

作品サイトはトップ `/` → 作品ページ `/works/november-kyusai/` → アプリ `/11月の救祭/app/` の順で進みます。作品ページとアプリ上部には互いのページへ戻るリンクがあります。

アプリ画面はスマートフォンで横幅いっぱい、PCで最大480pxの縦長表示です。ヘッダー直下に現在の問題番号を表示し、右端のトグルで問題一覧を開けます。「スタート」は「WeBotの使い方」を表示する初期画面へ戻り、回答エリアは閉じたままです。通常プレイでは、解答済みの問題とこれから解く問題だけを問題番号メニューに表示します。Q3の4つの問いとN6を完了するまではQ4を表示せず、Q3の小問やN6はメニューへ個別に追加しません。000000のデバッグでは全問題を選択できます。番号を選ぶと解答済みでもその問題の回答エリアを開き、直前の問題の正解後の会話を背景に表示します（N1の回答中はスタートの使い方案内、N2はN1の会話）。会話を挟まない小問はさらに前の会話を引き継ぎます。番号選択だけでは正解記録・会話履歴を追加しません。解答済みの番号にはチェックを表示します。ハンバーガーメニューからトーク・ヒント・履歴・再開番号・トラブル・タイトルに戻るを選べます。Q1以降の問題では「手がかり」も表示され、画面上部のボタンと同じ手がかり画面を開けます。ボタンの再押下・メニュー外のクリック・Escで閉じます。ホバー・フォーカス・押下時はグレーで表示します。

会話履歴の上部には手がかり画面と共通の戻るボタンがあり、トークの元の位置へ戻れます。立ち絵と章背景には軽量なWebPを使い、会話中にその場面の立ち絵と最初の案内写真を先読みします。案内写真の一覧には縮小版を使い、タップすると原寸の写真を開きます。

問題形式は `fields`（複数欄の文字入力、欄の順序とすべての正解を判定）、`text`（文字入力）、`single`（1つ選択）、`multiple`（複数選択）。問題番号は冊子と対応させて任意に設定できます。文字入力はNFKC・前後空白除去・英字の小文字化で比較します。複数選択は過不足なく一致する必要があります。

問題に `standalone: true` を指定すると、問題番号メニューから単独で開けますが、前後の問題との順次進行を接続しません。Q8はこの指定を使わず、Q7の会話後の回答ボタンから接続しています。

進行状況は、ブラウザ内とCloudflare Pages Functions＋D1に保存します。ブラウザに記録がなければ6桁の再開番号入力画面を表示し、「新しくはじめる」で`000001`〜`999999`の重複しない番号を発行します。同じブラウザでは「つづきから」、別の端末では番号入力で再開できます。番号は先頭の0を保持し、全角数字は半角に揃えます。ログイン・メールアドレス登録はありません。

`000000`は保存しないデバッグ専用です。進行はメモリ上だけで管理し、API送信やlocalStorageへの書き込みを行いません。既存の通常記録を変更せず、再読み込みでデバッグ進行を破棄します。ヘッダー下のデバッグ帯は表示せず、メニューの「再開番号」からデバッグ状態を確認できます。

保存対象は解答記録、会話、ヒント、分岐、考察に加え、表示中の画面、会話の再生位置、資料の選択位置です。短時間の変更をまとめて同期し、通信失敗時は端末内の未送信データを保持して再送します。「つづきから」では、未送信分がなければCloudflareの最新記録を取得し、通信できなければ端末の記録で続けます。別端末・複数タブの保存が競合すると、Cloudflareに保存済みの進行と画面を自動で読み直します。競合した記録はブラウザ内の退避領域にも残します。

新しい保存キーは`play-save:${scenario.id}`、退避記録は同じキーの`:archives`です。従来の`webbot:${scenario.id}`は移行元として読み取り、初回継続時にローカルの未同期記録へ取り込みます。Cloudflareへの移行成功後は`:migrated`マーカーで旧記録の再取り込みを止め、元データ自体は保持します。作品IDは`november-kyusai-v4`を維持し、旧番号・廃止小問の扱いは`engine.js`の復元処理に従います。

保存APIを含めてローカル確認するには、Node.js 24以降で`npm run dev:saves`を実行します。`artifacts/play-saves-local.sqlite`に実SQLiteの確認用DBを作り、本番と同じAPI処理を使用します。通常の`npm run dev`は静的表示だけを確認するモードで、`000000`のデバッグを利用できます。Cloudflare設定・公開・ロールバックの手順は[CLOUDFLARE_PLAY_SAVES.md](CLOUDFLARE_PLAY_SAVES.md)を参照してください。
